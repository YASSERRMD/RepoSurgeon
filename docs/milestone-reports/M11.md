## Fixes made during the milestone (real bugs found and corrected)

1. `ParseFailures` emitted a separate build failure for the indented `file.go:line` line under `--- FAIL`, double-counting; the location is now attached to the open failure group.
2. Unknown command profiles surfaced as 500s; they now return 400 with the profile name.
3. Check and patch routes were only registered when their service was configured, so a disabled service pretended the endpoint did not exist; they now return 503.
4. The profile registry lacked the `Name` field, so the API could not echo which profile ran.

## Remaining risks / limitations

- Check results are stored in-process; the durable `check_plans`/`check_attempts` tables land with the M12 persistence follow-up.
- Process-level CPU/memory limits are enforced by the runner image; cgroup enforcement inside the sandbox lands with M07's Linux runner work.
- The multi-stage matrix viewer (targeted → module → full suite → browser) is modelled by the profiles and the list endpoint; the browser smoke stage is executed as an E2E profile later.
