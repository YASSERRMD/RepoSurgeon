## Security and architecture checks

- [x] Tenant isolation: cross-org reads/writes impossible by construction (scoped queries) and tested at store and HTTP layers
- [x] Role enforcement: viewer cannot create projects; non-member cannot create projects; owner role granted only at organization creation
- [x] Idempotency prevents duplicate external effects; replay fingerprints the request body
- [x] Optimistic concurrency prevents lost updates on settings
- [x] Audit trail is append-only (database trigger rejects UPDATE/DELETE) and carries correlation IDs
- [x] Credential storage remains metadata-only in this milestone (no secret column exists)
- [x] OpenAPI contract and generated client drift-free
- [x] Git author/committer `yasserrmd`, no AI/co-author trailers (CI job)

## Fixes made during the milestone (real bugs found and corrected)

1. `Audit.Append` generated 10 placeholders for 9 columns → 42601 on insert; fixed the column count constant.
2. `store.Page` duplicated `domain.Page` and leaked a `has_more` field → consolidated onto the domain type as an alias.
3. `api.WriteError` ignored structured `Error.Details` → clients lost `current_version` on 409s; now falls back to the Error's own details.
4. Router-generated plain-text 404/405 replaced by a real method-aware router (M00) remained, and M01 confirms 404/405 JSON with `allowed_methods`.
5. Mobile header navigation overflowed the viewport at 390px → caught by the existing responsive E2E test; header now wraps.
6. Migration integration tests coupled to pre-applied migrations in a shared database → per-run schema isolation makes them repeatable anywhere.

## Correction carried by this PR

The M00 merge (PR #1) landed an earlier branch ref, so three M00 fixes were
missing from `main`: the golangci-lint version pin, the runner network change
(its healthz/exec were unreachable because the network was `internal: true`),
and the smoke-script runner wait. Those changes are re-applied here as a single
commit (`m01: keep health routes subject-free, pin lint version, fix runner
network and gitleaks token`) so this PR restores a green `main`. M01 also fixes
two genuine defects found by CI: `/health/ready` returned 401 while the subject
middleware was wrapped around health routes (it now reports 503 during an
outage, with a regression test), and the gitleaks action now receives
`GITHUB_TOKEN`.

## Remaining risks / limitations

- Authentication is still the M01 development subject resolver (`X-Dev-Subject`, `developer@localhost` default). It is installed only outside production and production requests receive 401; M02 replaces it with real sessions. This is the single largest interim risk and is called out in the API contract description.
- Run/test/approval tables are created but not yet written by any flow; that behaviour arrives with M06–M07.
- No seed/fixture migration exists by design; evaluation fixtures live under `fixtures/` and are generated by `scripts/make-fixture-repo.sh`.
