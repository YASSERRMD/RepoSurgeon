## Bugs found and fixed during the milestone (real, not cosmetic)

1. Loop detection evaluated only recorded history, so an identical diff was applied a second time before the loop was proven; `FindWithProposed` now refuses the duplicate before it runs.
2. `ParseFailures`-adjacent verdict classification could report green for an attempt that merely did not run; verdicts now derive only from the executed check.
3. The journal was not the source of truth for timestamps (an appended entry could carry an empty `CreatedAt`, which also made ordering unreliable once formatting trimmed trailing zeros); entries are now stamped on append and never re-sorted.
4. `blockedStatus` read the sentinel instead of the blocked kind, so loop detection answered 400 instead of 409; it now maps loop→409 and budget→429.
5. The recovery journal was not written on the success path, so a scheduled retry was invisible in the timeline.
6. gosec flagged the expired-credential identifiers as hardcoded credentials; the exclusion records that the word only names the failure class.

## Remaining risks / limitations

- Check re-run after a rollback is gated on a configured runner; without one the endpoint reports drift counts and the restored verdict instead of claiming a green suite.
- Postgres is the durable store of record; the in-memory journal/receipt/tracker implementations remain for unit isolation, and the API uses the durable repositories.
- Recovery budgets are per run and per class; a cluster-wide rate-limit budget across runs is not yet shared.
