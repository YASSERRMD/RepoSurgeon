## Bugs found and fixed during the milestone

1. `Open` was not serialized, so concurrent webhook deliveries created four pull requests from five deliveries; the check-then-create sequence is now serialized and the durable `UNIQUE (run_id, effect_id)` remains the production backstop.
2. The verified merge record did not carry the stored identity, so it saved as a new row and the deleted-branch state was lost; the stored repository, branch and identifiers are now carried over.
3. A replayed create answered 400 ("produced no commit") instead of returning the recorded pull request; the existing PR is now looked up before any composition happens.
4. `blockedStatus`/`RepoPolicyMergeable` let an unprotected non-main branch be merged by default; merging now requires branch protection unless the operator explicitly configures otherwise.
5. `gate` refusal reasons were returned through the generic error mapper, which turned a 400/409 refusal into a 500.

## Remaining risks / limitations

- A real GitHub smoke run against a disposable fixture repository requires an owner-provided App installation; the contract suite exercises a faithful fake with GitHub's own state machine instead, which is recorded here as the actual verification performed.
- Push is performed by the trusted Git service; the physical `git push` command line is the same seam the workspace manager uses, so the adapter owns the short-lived token end to end.
- Merge-method effects on commit history (squash/rebase) are recorded from GitHub's response rather than verified independently.
