## Security and architecture checks

- [x] Git commands never go through a shell; arguments are validated or fixed
- [x] Workspace ids, worktree names and branch names are strictly validated
- [x] Output and runtime are bounded; a hanging Git command fails fast
- [x] The source repository is never modified (clone is detached at the pinned SHA)
- [x] Workspace HTTP routes require `project.write`/`project.read` and are audited
- [x] The workspace root is a dedicated directory (`RS_WORKSPACE_ROOT`), not the repository root
- [x] OpenAPI contract and client drift-free

## Fixes made during the milestone (real bugs found and corrected)

1. `Diff` compared against `HEAD`, which hid already-committed work; it now takes the base ref and the callers pass the pinned SHA.
2. Workspace id validation accepted spaces and traversal components; it now uses the shared name validator.
3. Handler tests used a blanket project stub that hid cross-tenant access; the fake now returns 404 for unknown organizations and ids.

## Remaining risks / limitations

- Worktrees are created and destroyed by the API in this milestone; the durable worker-driven lifecycle (leases, restart recovery) arrives with M06.
- Repository cloning uses the local filesystem URL in tests; authenticated GitHub clones for real repositories arrive with M13's push/PR flow.
- Network egress from workspace processes is not yet blocked at the namespace level (M07).
