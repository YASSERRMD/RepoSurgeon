## Fixes made during the milestone (real bugs found and corrected)

1. Plan approval errors surfaced as 500s; they now map to 409 `plan_conflict` and 404.
2. Plan verification errors surfaced as 500s; they now return 422 with the failing reason.
3. Plan routes were only registered when the service was configured, so an unconfigured server pretended the endpoints did not exist; they now return 503 `plans_unavailable`.

## Remaining risks / limitations

- Plan persistence is in-process with a `SaveDraft`/`Approve` surface; the `plans`, `plan_nodes`, `plan_acceptance`, `plan_findings` and `plan_approvals` tables are migrated and the schema is exercised, and the durable store lands with the M10 persistence follow-up.
- The model-driven plan generation call (Step 5 proposing the plan JSON) is wired through the same validation path but invoked from the worker in M12; the M09 surface validates, verifies and stores what it receives.
- `base_sha`/`out_of_scope`/`assumptions` are accepted on submission and are not yet echoed by the store projection; the UI states that explicitly instead of inventing values.
