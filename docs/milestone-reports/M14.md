## Bugs found and fixed during the milestone

1. The runs list advertised a `state` filter the API did not implement, which would have been a client-side trim presented as a filter; the filter is now a real SQL predicate with validation, and the contract documents it.
2. The shell navigation pointed `/runs` at the context inspector and listed two entries for the same route; the runs list now owns `/runs` and the inspector is run-scoped.
3. A signed-in visitor was redirected to the public status page; the guard now sends them to the overview.
4. The dashboard section previously read runs' states without auditing the aggregate; a store failure is now surfaced as an error state rather than an empty screen.

## Remaining risks / limitations

- The Evaluations section (M17 benchmark laboratory) has no backend yet, so it is deliberately absent from the navigation rather than shipped against invented data.
- The issue-to-run wizard (choosing project, issue, branch, model, effort, budget and policy) is delivered as the run creation flow behind `POST /api/v1/runs` plus the issues/pull-request screens; a dedicated multi-step wizard remains a follow-up once the run creation payload carries model and budget fields end to end.
- Playwright specs run against the composed stack in CI; they cannot be executed locally here because Docker Desktop cannot start, which is recorded rather than passed.
